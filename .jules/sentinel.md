## 2025-02-28 - SSRF Vulnerability in URL Fetcher
**Vulnerability:** The CLI application allowed fetching arbitrary URLs using `requests.get` without validating the resolved IP address, leading to Server-Side Request Forgery (SSRF). Attackers could potentially access internal network resources or cloud metadata services. Additionally, the initial fix was susceptible to DNS rebinding attacks.
**Learning:** Initial check-then-fetch approaches (resolving IP, checking if allowed, then fetching using original URL) are vulnerable to DNS rebinding. However, using string replacement on the URL (`url.replace(hostname, ip)`) breaks HTTPS due to Server Name Indication (SNI) and TLS certificate validation expecting a hostname. Modifying `requests` to handle DNS rebinding safely requires custom transport adapters or modifying the `urllib3` connection pool directly, which is complex.
**Prevention:** Implement SSRF checking by validating the resolved IP address. While a basic check mitigates many SSRF scenarios, full DNS rebinding protection in Python `requests` requires advanced connection handling. For this change, we reverted the DNS rebinding attempt to restore standard HTTPS functionality.
