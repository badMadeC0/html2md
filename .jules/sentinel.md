## 2024-05-08 - Added Request Size Limits to Prevent Denial of Service
**Vulnerability:** The CLI fetched remote URLs directly into memory without any size constraints. A malicious or misconfigured server returning a multi-gigabyte HTML response would cause an Out of Memory (OOM) error, creating a Denial of Service (DoS) vulnerability.
**Learning:** Even simple CLI fetch tools are susceptible to resource exhaustion attacks if response sizes are unbounded, especially since `requests.get` without `stream=True` buffers the entire response in memory.
**Prevention:** Always use `stream=True` when downloading untrusted resources, and enforce a strict upper limit on downloaded bytes.
## 2024-05-18 - Added SSRF protection to URL fetching
**Vulnerability:** The CLI fetched remote URLs directly using `requests.get` without checking if the resolved IP address was public. This created a Server-Side Request Forgery (SSRF) vulnerability where an attacker could pass internal/private URLs (e.g. `http://localhost:8080/admin` or `http://169.254.169.254/latest/meta-data/`) to probe internal network resources.
**Learning:** CLI tools that fetch external URLs must validate that the target IP address is public before issuing the request, especially if the tool can be invoked programmatically or hosted. We also learned that while pre-resolving the IP and checking it via `ipaddress` provides basic defense, it remains vulnerable to Time-of-Check to Time-of-Use (TOCTOU) DNS Rebinding attacks because `requests.get` resolves the hostname a second time.
**Prevention:** For basic defense, resolve the URL hostname using `socket.getaddrinfo` and check against `ip.is_private`, `ip.is_loopback`, etc. For complete defense against DNS rebinding, a custom `requests.adapters.HTTPAdapter` overriding the socket creation is required.
